## 第一部分：给 AI 的指令（整段复制）

> 把你派给的那个 AI（Claude / ChatGPT / DeepSeek 都行）打开，把下面**整段**复制给它。

---

````
我要给 DeepSeek Harness（简称 DSH）接入第三方 AI 模型的 API。请你帮我完成，
过程中每一步都告诉我你在做什么，失败的话说清楚原因。

### 背景
DSH 是 DeepSeek 出的桌面版 AI 客户端（macOS app）。它默认只能用自己的模型，
但支持接入任何「OpenAI 兼容」或「Anthropic 协议」的第三方服务商
（比如 APIYi、七牛云、OpenRouter、各类中转站）。

### 关键信息
- DSH 版本：0.2.2-rc.1（如果版本不同，配置字段可能略有差异，以实际为准）
- 配置文件位置：`~/.dsh/profiles/desktop/cordis.patch.yml`
- 自定义模型插件：`@deepseek-ai/dsh-llm-pi-ai`（DSH 自带，无需安装）

### 两种接入方式，请优先用方式 A

### 方式 A：图形界面（推荐，更简单）
1. 打开 DSH → 左下角「设置」
2. 左侧选「模型」
3. 点底部的「+ 添加模型提供商」
4. 依次填写：
   - Provider ID：全小写英文，创建后不能改名（如 `myapi`）
   - Display name：显示名（如 `我的中转站`）
   - Base URL：服务商给的接口地址（OpenAI 兼容的通常以 `/v1` 结尾）
   - API protocol：选 `OpenAI compatible`（如果服务商是 Anthropic 原生协议就选 Anthropic）
   - API Key：服务商的密钥
5. 点「Fetch available models」自动拉取模型列表
6. 勾选你需要的模型 → 保存

**注意：如果这个界面里没有「添加模型提供商」按钮，说明版本较旧，请改用方式 B。**

### 方式 B：修改配置文件
1. 先备份配置文件（重要！）：
   ```bash
   cp ~/.dsh/profiles/desktop/cordis.patch.yml \
      ~/.dsh/profiles/desktop/cordis.patch.yml.bak-$(date +%Y%m%d-%H%M%S)
   ```
2. 在 `~/.dsh/profiles/desktop/cordis.patch.yml` **文件末尾**追加以下内容
   （注意缩进必须用空格，不能用 Tab；`-` 开头的行要顶格）：

```yaml
- insert:
    - id: llm-pi-ai
      name: "@deepseek-ai/dsh-llm-pi-ai"
      config:
        providers:
          你的providerID:
            displayName: "显示的名字"
            api: openai-completions
            baseURL: "https://服务商地址/v1"
            headers:
              Authorization: "Bearer 你的密钥"
            models:
              - id: 模型ID
                name: "模型显示名"
                contextWindow: 1000000     # ⚠️ 见下方「容量别写错」
                maxTokens: 128000
                input: ["text", "image"]
```

3. **容量别写错（第二容易踩的坑）**：
   - `contextWindow` 写小了 → 上下文很快就显示「已用 100%」，长对话被提前截断
   - 2026-11 的 Claude 真实容量：**Opus 5.5 / Sonnet 5.5 / Fable 5.x = 1M 上下文 + 128K 输出**
   - Claude Haiku 5.5 = 200K 上下文
   - Gemini 4 = 1M 上下文
   - 拿不准就去服务商文档或模型官网查，别凭感觉填

4. **最容易漏的一点**：每个 model 都必须写 `input: ["text", "image"]`。
   不写的话默认只有文本，模型就读不了图片（会报
   `model does not declare image input`）。

4. **完全退出 DSH 再重新打开**（macOS 按 ⌘Q，不是点红叉）。配置只在启动时读取。

### 方式 C：Anthropic 原生协议的服务商
如果服务商给的是 Anthropic 协议（不是 OpenAI 兼容），把 `api` 和 `headers` 换成：

```yaml
            api: anthropic-messages
            baseURL: "https://服务商地址"
            headers:
              x-api-key: "你的密钥"
              anthropic-version: "2023-06-01"
```

### 请按顺序做这些事
1. 先确认 DSH 版本和配置文件路径存在
2. 问我：服务商是什么？给的是 OpenAI 兼容地址还是 Anthropic 地址？
3. 按上面的方式操作（优先 A）
4. 改完让我重启 DSH
5. 重启后陪我验证（见下面「验证清单」）

### 验证清单（重启后逐项确认）
- [ ] DSH 能正常启动，没有白屏或闪退
- [ ] 「设置 > 模型」里能看到我新加的 provider
- [ ] 对话窗口顶部的模型列表里能选到新模型
- [ ] 选一个模型随便问一句，能正常回复
- [ ] 让 AI 读一张图片，能描述出内容（如果模型支持看图）

### 如果出问题
配置文件备份在 `~/.dsh/profiles/desktop/cordis.patch.yml.bak-*`，
用下面命令恢复然后重启：

```bash
cp ~/.dsh/profiles/desktop/cordis.patch.yml.bak-<时间戳> \
   ~/.dsh/profiles/desktop/cordis.patch.yml
```
````

## 第二部分：给人看的操作步骤

> 这部分是给**完全不懂电脑的人**看的。每一步都写清楚了「点什么、看到什么、填什么」。

### 准备工作（5 分钟）

#### 1. 确认你装的是 DSH 桌面版

- 打开电脑上的 **DeepSeek Harness**（图标是一条鲸鱼）
- 能正常打开、能聊天，就说明装好了

#### 2. 拿到服务商的三个东西

向给你服务的人要**这三样**（缺一不可）：

| 要什么 | 长什么样 | 举例 |
|---|---|---|
| 1. 接口地址 | 一个网址 | `https://api.example.com/v1` |
| 2. 密钥 | 一长串字母数字 | `sk-abc123def456...` |
| 3. 协议类型 | 说「OpenAI」或「Anthropic」 | OpenAI |

**把这三个写在纸上或记事本里，别弄丢。**

#### 3. 确认能用

打开浏览器，把「接口地址」贴进去回车：
- 看到**乱码或报错**都正常（说明地址通）
- **完全打不开**说明地址错了，回去问

### 开始配置

### 方式一：在界面里点（推荐，最简单）

#### 第 1 步：打开设置

1. 打开 DSH
2. 看**左下角**，有个**齿轮图标**（⚙️）
3. 点它

> 如果左下角没有齿轮，点左上角的头像，菜单里也能找到「设置」

#### 第 2 步：找到「模型」

设置窗口打开后，**左边有一列菜单**：

```
账号与余额
通用设置
👉 模型        ← 点这个
内置插件
Agent 预设
归档对话
```

#### 第 3 步：点「添加模型提供商」

右边页面会显示你现在的模型列表（比如「DeepSeek 账号」「APIYi Claude」等）。

**最下面**有个虚线的方框，写着：

```
┌────────────────────────────┐
│  ＋ 添加模型提供商           │  ← 点这个
└────────────────────────────┘
```

#### 第 4 步：填表

弹出的窗口要填 5 项。**照着填**：

| 框里写什么 | 你填什么 |
|---|---|
| **Provider ID** | 随便起个英文小写名，比如 `myapi`（**用了一次就不能改，起个简单的**） |
| **Display name** | 显示的名字，随便填，比如「我的模型」 |
| **Base URL** | 粘贴服务商给的**接口地址** |
| **API protocol** | 点开选 `OpenAI compatible`（服务商说 Anthropic 才选 Anthropic） |
| **API Key** | 粘贴服务商给的**密钥** |

#### 第 5 步：拉模型列表

填完后找一个按钮，可能叫：

- `Fetch available models`
- `获取可用模型`
- `拉取模型`

**点它**。等几秒，下面会出现一堆模型名字，前面有小方框。

#### 第 6 步：勾选 + 保存

1. **勾上**你想要的模型（想全要就全勾）
2. 找**保存**按钮（`Save` / `保存`），点它
3. 关掉设置窗口

#### 第 7 步：重启 DSH（重要！）

1. 按键盘 **⌘ + Q**（Command 键 + Q 键）
   > 这是**完全退出**，不是关窗口
2. 等 3 秒
3. 重新打开 DSH

#### 第 8 步：切换模型试试

1. 在对话窗口**顶部**，找到当前模型名（比如显示「DeepSeek-V4-Flash」）
2. **点它**
3. 弹出列表，应该能看到你刚加的服务商，下面挂着模型名
4. **点一个模型**
5. 随便发句「你好」，能回复就成功了

## 第四部分：进阶配置

### 网页抓取（免费，强烈建议开）

DSH 默认的网页抓取要花钱（走 DeepSeek 的付费接口）。可以换成免费的：

配置文件 `~/.dsh/profiles/desktop/cordis.patch.yml` 里找到 `- id: web` 这一段：

```yaml
- id: web
  name: "@deepseek-ai/dsh-web"
  config:
    searchProvider: deepseek-search-api
    fetchProvider: http          # ← 改成 http，这一项就免费了
```

### 网页搜索（必须付费）

搜索功能只能用 DeepSeek 的搜索服务，**必须有 DeepSeek 的 API 密钥**：

1. 打开 https://platform.deepseek.com
2. 注册/登录
3. 左侧「API keys」→「创建 API key」
4. 复制生成的 key（**只显示一次，立刻存好**）
5. 回 DSH → 设置 → **内置插件** → 找到「网页搜索与获取」→ 填进去

> **注意**：这个 key 和模型服务商的 key **不是一回事**，不能混用。

### 接入多个服务商

重复【第二部分】的操作即可。每个服务商起**不同的 Provider ID**。

## 第五部分：出问题怎么办

### 症状 1：DSH 打不开了 / 一直白屏 / 闪退

**原因**：配置文件写错了。

**急救（3 步）**：

1. 打开「终端」（在「启动台」里搜「终端」）
2. 复制下面这行粘贴进去，回车：
   ```bash
   ls -t ~/.dsh/profiles/desktop/cordis.patch.yml.bak-* | head -1
   ```
   会显示一个文件名，比如 `/Users/你的名字/.dsh/profiles/desktop/cordis.patch.yml.bak-20261116-153253`
3. 复制下面这行，把 `<上面显示的文件>` 换成刚才那个文件名，回车：
   ```bash
   cp <上面显示的文件> ~/.dsh/profiles/desktop/cordis.patch.yml
   ```
4. 重新打开 DSH，应该恢复了

### 症状 2：模型列表里看不到新服务商

**检查顺序**：

1. **真的重启了吗？** 必须 ⌘+Q 完全退出，不是关窗口
2. **配置文件保存了吗？** 用文本编辑打开确认内容还在
3. **缩进对吗？** YAML 对空格极其敏感，必须用**空格**不能用 Tab
4. **providerID 重复了吗？** 两个服务商不能用同一个 ID

### 症状 3：模型能选，但发消息报错

报错文字 → 对照解决：

| 报错里有什么 | 问题 | 怎么办 |
|---|---|---|
| `401` / `Unauthorized` | 密钥错了 | 重新复制密钥，注意别带空格 |
| `404` / `not found` | 地址错了 | 检查 Base URL，OpenAI 兼容的要带 `/v1` |
| `model not found` | 模型 ID 错了 | 检查模型 ID 拼写 |
| `does not declare image input` | 漏了图像声明 | 加 `input: ["text", "image"]` |
| `MISSING_CREDENTIAL` | 没找到密钥 | 检查 `headers` 或 `apiKeyEnv` |
| 超时 / `timeout` | 网络问题 | 检查能不能打开服务商网址 |

### 症状 4：能对话但读不了图

模型本身支持看图的话，99% 是配置里漏了 `input`。找这段补上：

```yaml
                input: ["text", "image"]
```

### 症状 5：网页搜索报 `DEEPSEEK_API_KEY`

正常现象。搜索走的是 DeepSeek 的付费服务，需要单独配 key（见【第四部分】）。

**不想花钱的话**：网页抓取（抓已知网址）已经免费了，只是不能「搜索」。

## 附录：各模型真实容量对照

> **这是最容易填错的地方**。2026-11 实测校正值，填小了会导致「上下文已用 100%」提前出现。

| 模型 | 上下文窗口 | 最大输出 | 来源 |
|---|---|---|---|
| Claude Opus 5.5 | 1,000,000 | 128,000 | Anthropic 官方模型总览 |
| Claude Sonnet 5.5 | 1,000,000 | 128,000 | 同上 |
| Claude Fable 5.x | 1,000,000 | 128,000 | 同上 |
| Claude Haiku 5.5 | 200,000 | 64,000 | Haiku 系列惯例（官方未明示 5.5） |
| Gemini 4 Argon | 1,048,576 | 65,536 | Google Cloud 官方（输入+输出共享同一个额度） |
| Gemini 4 Carbon | 1,048,576 | 65,536 | 同上 |
| Gemini 3.x / 2.5 | 1,048,576 | 65,536 | 输入 1M、输出 64K 分开计 |

**填错的后果**：
- `contextWindow` 填小 → 对话很快显示「已用 100%」，长任务被提前截断
- `contextWindow` 填大 → DSH 会推迟压缩，实际超限时 API 报错
- `maxTokens` 填太大 → 可能被服务商拒绝（超过其上限）

**拿不准怎么办**：去模型官网查，或直接问服务商客服。别凭感觉填。

## 附录：常见服务商参数

> 地址和协议类型以服务商实际给的为准，下面只是参考。

| 服务商 | Base URL | api | 备注 |
|---|---|---|---|
| **APIYi** Claude | `https://api.apiyi.com` | `anthropic-messages` | 原生 Anthropic 协议 |
| **APIYi** Gemini | `https://api.apiyi.com/v1` | `openai-completions` | OpenAI 兼容 |
| **七牛云** | `https://api.qnaigc.com/v1` | `openai-completions` | 聚合 25+ 国产模型 |
| **StepFun** | `https://api.stepfun.com/step_plan/v1` | `openai-completions` | 用 Step Plan 时选 step_plan |
| **OpenRouter** | `https://openrouter.ai/api/v1` | `openai-completions` | 海外聚合 |
| **Ollama**（本地） | `http://localhost:11434/v1` | `openai-completions` | 本机跑模型，免费 |

### Anthropic 协议的 headers 写法

```yaml
            headers:
              x-api-key: "你的密钥"
              anthropic-version: "2023-06-01"
```

### OpenAI 兼容的 headers 写法

```yaml
            headers:
              Authorization: "Bearer 你的密钥"
```
